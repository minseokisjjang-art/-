# MVP 브리프 v2 — 걸음수/타이핑 반응형 고양이 앱 (친구 마당)

> v1 브리프 리뷰 결과를 반영한 수정판. 방향과 범위 관리는 그대로 살리고,
> 현재 저장소 상황·플랫폼 제약·비용 현실을 반영해 수정했다.

---

## 총평 (리뷰 요약)

v1 브리프의 방향은 좋다. 특히 "하지 말 것" 목록(실시간 동기화 컷, 채팅 컷,
커스터마이징 컷)은 MVP 범위 관리로서 훌륭하다. 다만 아래 4가지는 전략적으로
수정이 필요하다.

1. **현재 저장소와의 관계가 브리프에 없다.** 이 저장소에는 이미 "햄스터 목장"
   PWA 프로토타입이 있다 — 터치 반응, MQTT 기반 실시간 멀티플레이, 가챠·꾸미기·장터까지.
   브리프는 Expo 신규 앱을 전제하므로 **사실상 재작성**이다. 걸음수가 핵심 가치라면
   재작성이 맞다(웹에는 만보계 API가 없어 PWA로는 불가능). 이 결정을 명시하고,
   기존 프로토타입에서 **포팅할 자산 목록**(행동 AI, 애니메이션 상태기계, 초대 코드 UX,
   이모트)을 적어야 한다.
2. **걸음수 감지의 플랫폼 현실.** `expo-sensors`의 일일 누적 걸음수 조회
   (`getStepCountAsync`)는 **iOS 전용**이다. Android는 Health Connect 연동이 필요하고,
   이는 **Expo Go에서 안 돌아간다** → development build 필요. 개발 순서에 반영해야 한다.
3. **백그라운드 동기화는 MVP에서 컷.** iOS/Android 모두 백그라운드 실행 주기를
   OS가 보장하지 않는다. 다행히 걸음수는 앱이 꺼져 있어도 OS가 계속 세 준다
   (iOS CMPedometer 7일 보관, Health Connect 동일). **앱을 열 때만 동기화해도
   데이터 손실이 없다** — 신선도만 떨어지는데, 이건 "마지막 활동 시각" 표시가 커버한다.
4. **비용 표에 빠진 것: iOS 배포비.** 친구 아이폰에 앱을 깔아주려면 TestFlight가
   필요하고, 이는 Apple Developer Program **연 $99**다. 이게 이 프로젝트의 사실상
   유일한 실비용이다. (Android는 APK 직접 공유 0원.)

그 외 작은 수정: 전화번호 인증 컷(SMS 업체 연동 = 유료), 역전 푸시 알림 컷(서버
로직 필요), RLS 보안 명시, 날짜 타임존(KST) 명시, 랭킹을 3순위로 승격.
테마도 결정 필요: 저장소는 v1.2에서 햄스터로 피벗했는데 브리프는 고양이다 —
자산 구조상 동물 스왑은 쉬우니 큰 문제는 아니지만 정하고 시작하자.

---

## 한 줄 개요 (유지)

사용자의 걸음 수와 (앱 내) 타이핑에 반응해 고양이가 움직이고, 초대한 친구들의
고양이도 한 화면(마당)에서 함께 볼 수 있는 앱. 캐시워크의 무과금 버전 +
봉고캣의 모바일 버전을 결합한 소셜 위젯형 앱.

---

## 선행 결정 (새로 추가)

| 결정 | 권장 | 근거 |
|---|---|---|
| 걸음수가 핵심 가치인가? | **예 → Expo 신규 앱 확정** | 웹(PWA)에는 만보계 API가 없다. 걸음수를 포기하면 기존 PWA + Supabase라는 훨씬 싼 경로도 있으나, 캐시워크 콘셉트라면 걸음수가 코어다. |
| 기존 PWA에서 가져올 것 | 행동 AI · 애니메이션 상태기계 · 초대코드 UX · 이모트 리액션 | JS 로직이라 RN으로 포팅 용이. 가챠/장터/꾸미기는 이번 버전에서 제외(코드는 남아 있으니 추후 복원 가능). |
| 테마 | 고양이 or 햄스터 중 택 1 | 스프라이트만 갈아끼우면 되는 구조로 만들 것. |

## 기술 스택 (수정)

| 영역 | 선택 | v1에서 달라진 점 |
|---|---|---|
| 앱 프레임워크 | React Native (Expo) | 유지. 단 Android 걸음수부터는 **development build** 필요 (Expo Go 불가) |
| 걸음수 — iOS | expo-sensors (CMPedometer) | 유지. 지난 7일 조회 가능 |
| 걸음수 — Android | **Health Connect** (react-native-health-connect) | 명시. expo-sensors의 일일 누적 조회는 iOS 전용 |
| 타이핑 반응 | 로컬 상태 (React state) | 유지 |
| 서버 | Supabase (Postgres) | 유지. 단 **RLS + RPC 필수** (아래 보안 참조) |
| 인증 | **Supabase 익명 로그인만** | 전화번호 인증 컷 — SMS 업체(Twilio 등) 연동이 유료 |
| 초대 | **6자리 초대코드만** | 딥링크 컷 — 스토어 배포 전 커스텀 스킴은 카톡에서 안 열리고, 유니버설 링크는 도메인+설정 필요. v2로 |
| 푸시 알림 | 컷 (v2로) | "역전" 판정에 서버 로직(Edge Function + 트리거) 필요. MVP 가치 대비 과함 |

**익명 로그인의 한계 (감수하고 명시):** 앱 삭제·기기 변경 시 계정과 마당이
사라진다. MVP에서는 감수, v2에서 이메일/소셜 계정 연동 추가.

## MVP 기능 리스트 (수정)

### 1순위 — 나만의 고양이 (유지)
- 걸음 수에 따라 고양이 애니메이션 변화 (걷기/뛰기/낮잠)
- 앱 내 메모장 입력 시 고양이가 반응
- 오늘 걸음 수 로컬 표시

### 2순위 — 친구 초대 (유지, 세부 수정)
- 닉네임 설정 (익명 로그인 위에)
- "마당 만들기" → 초대코드 자동 생성
  - 숫자 6자리(100만 조합) 대신 **영대문자+숫자 6자리, 혼동 문자(0/O/1/I) 제외** (~8억 조합)
- 초대코드 입력으로 마당 참여 — **참여/생성은 RPC 함수로만** (테이블 직접 insert 금지)
- 한 마당 최대 8명 (유지)

### 3순위 — 공유 마당 화면 (유지) + 오늘 랭킹 (4→3순위 승격)
- 마당 참여자들의 고양이가 한 화면에 표시
- 각 고양이 옆에 닉네임 + 오늘 걸음 수 + 마지막 활동 시각
- **동기화는 앱 포그라운드 진입 시에만** (백그라운드 배치 컷)
- 오늘 걸음 수 랭킹: 이미 받아온 데이터를 정렬만 하면 되는데 리텐션 기여가 커서 승격

### v2 후보 (이번 버전에서 하지 않음)
- 역전 알림 — 푸시 대신 **앱 열 때 로컬 비교 배너**("어제 ○○가 너를 앞질렀어!")부터
- 원탭 상호작용 (쓰다듬기/콕 찌르기) — 기존 프로토타입에 이모트 자산 있음
- Supabase Realtime presence ("지금 접속 중" 표시) — 기존 MQTT 버전의 "함께 있는 느낌" 복원
- 딥링크 초대, 계정 연동(기기 변경 대비), 푸시 알림
- 고양이 커스터마이징 — 기존 프로토타입 가챠/꾸미기 코드 복원 + 수익화 검토

### 하지 말 것 (유지)
- 실시간 위치 공유 / 채팅·댓글 / 실시간 동기화(Realtime 구독)

## 데이터 & 보안

```
[내 폰: OS가 걸음수를 계속 집계 (앱 꺼져 있어도)]
   ↓ (앱 포그라운드 진입 시 오늘 걸음수 upsert)
[Supabase: daily_steps 갱신]
   ↓ (마당 화면 열 때 / 당겨서 새로고침)
[친구 폰: 마당 전원의 최신 걸음수 조회 → 고양이 렌더링]
```

테이블 (v1의 4개 유지, 세부 보강):

- `profiles` (id → auth.users 참조, nickname, created_at) — Supabase 관례상 users 대신 profiles
- `yards` (id, invite_code **unique**, created_by, created_at)
- `yard_members` (yard_id, user_id, joined_at) — PK (yard_id, user_id)
- `daily_steps` (user_id, date, step_count, updated_at) — PK (user_id, date)

**RLS 정책 (필수, v1에서 누락):**
- 익명 유저가 아무 마당이나 조회할 수 없어야 한다
- `yards`: 내가 멤버인 마당만 SELECT. 코드로 찾기는 `join_yard(code)` RPC 내부에서만
- `yard_members` / `daily_steps`: 같은 마당 멤버만 SELECT, 본인 것만 INSERT/UPDATE
- `create_yard()` / `join_yard(code)`는 SECURITY DEFINER RPC로 — 8명 제한·중복 참여 검사를 서버에서

**날짜 처리:** `daily_steps.date`는 **KST 기준으로 클라이언트가 계산**해서 보낸다.
(명시하지 않으면 자정 전후 UTC 경계에서 걸음수가 어제로 들어가는 버그가 난다.)

## 개발 순서 (수정)

1. Expo 신규 프로젝트 + 기존 PWA에서 행동 AI/애니메이션 포팅 → **1인용 완성** (Expo Go로 개발 가능: 타이핑 반응 + iOS 걸음수)
2. Android 걸음수: Health Connect 연동 → 이 시점부터 **development build 전환**
3. Supabase 프로젝트 + 테이블 4개 + **RLS + RPC 2개** 생성
4. 익명 로그인 + 닉네임 온보딩
5. 마당 만들기 / 초대코드 참여
6. 마당 화면 (참여자 그리드 + 고양이 애니메이션 + 걸음수/마지막 활동)
7. 포그라운드 진입 시 걸음수 동기화
8. 오늘 랭킹 정렬 표시
9. 친구 배포: iOS TestFlight / Android APK 공유 → **2대 이상 실기기에서 마당 검증**

v1의 조언대로 **1인용(1~2단계)을 먼저 완성해 확인한 뒤** 소셜(3단계~)로 넘어간다.

## 비용 재확인 (수정)

| 항목 | 비용 | 비고 |
|---|---|---|
| 걸음수 측정 / 애니메이션 | 0원 | 온디바이스 |
| Supabase | 0원 | 무료 티어(DB 500MB, 5만 MAU). **단, 1주일 미사용 시 프로젝트 일시정지** → 대시보드에서 수동 재개 |
| Android 친구 배포 | 0원 | APK 직접 공유. 스토어 등록 시 $25 1회 |
| **iOS 친구 배포** | **연 $99** | TestFlight = Apple Developer Program 필수. **이 프로젝트의 사실상 유일한 실비용** |
| 전화번호 인증 | 컷 | SMS 업체 연동 유료 → 익명 로그인으로 회피 |

친구 중 아이폰 사용자가 있다면 연 $99는 피할 수 없다. 전원 Android라면 완전 0원 운영 가능.
